# Исторический арбитражный сканнер

Надстройка над калькулятором: вместо одной текущей котировки собирает
постоянно обновляемую историю заданной глубины, ищет по ней связки
`USDT → … → USDT` и строит график произведения курсов во времени.

Исходные модули (`arb_core.py`, `exchanges.py`, `dexes.py`, `app.py`)
не тронуты — они по-прежнему считают сделку по реальному стакану.

---

## Быстрый старт

```bash
pip install -r requirements.txt

python selftest.py              # 1. проверить, что источники доступны
python -m history.collector     # 2. запустить сбор (отдельное окно, не закрывать)
streamlit run app.py            # 3. интерфейс, страницы слева
```

Сборщик и интерфейс — разные процессы. Сборщик пишет в SQLite, интерфейс
читает. Браузер можно закрыть, сбор не остановится.

## Настройка

Всё в `history/config.py`, класс `Settings`:

| Параметр | По умолчанию | Смысл |
|---|---|---|
| `chain` | `bsc` | сеть DEX |
| `quote_asset` | `USDT` | вход и выход всех связок |
| `dex_pool_limit` | 100 | сколько топовых пулов наблюдать |
| `min_pool_reserve_usd` | 100 000 | пулы меньше не берём: маржу съест проскальзывание |
| `history_days` | 7 | глубина истории |
| `timeframe` | `1m` | гранулярность |
| `max_legs` | 4 | максимум ног в связке |
| `trade_size_usd` | 1000 | объём, под который считается проскальзывание |
| `staleness_sec` | 180 | предельный возраст котировки |
| `spot_only` | `True` | отсекать токены с плечом (BTC3L, ETHUP и подобные) |

Те же значения переопределяются ключами командной строки:

```bash
python -m history.collector --days 30 --timeframe 5m --pools 200
python -m history.collector --no-dex        # только биржи
python -m history.collector --once -v       # один проход, подробно
```

## Как считается маржа

Маржа связки — произведение курсов всех ног, каждый уже за вычетом издержек:

```
итог / старт = ∏ ( курс_i × (1 − комиссия_i) × проскальзывание_i ) − газ
```

**Комиссии.** Для CEX — тейкерские ставки из `CEX_TAKER_PCT`. Для DEX
комиссия пула уже сидит в цене, отдельно не начисляется.

**Проскальзывание.** Для DEX точно, по формуле пула постоянного произведения:
своп размера `S` против резерва `R` даёт курс хуже спота в `R/(R+S)` раз,
где `R` — половина TVL пула. Для V3 ликвидность около текущей цены
концентрированнее, чем следует из общего TVL, поэтому оценка занижает
исполнимый объём — ошибка в безопасную сторону.

Для CEX точного расчёта нет: стакана в истории не существует, есть только
свеча. Используется оценка по обороту — сделка в долю `v` от минутного
оборота двигает цену примерно на `v/2`, с потолком 2%. Это ОЦЕНКА;
на ликвидных парах поправка близка к нулю и не искажает результат,
на неликвидных отсекает заведомо неисполнимое.

**Токены с плечом.** По умолчанию отсекаются: `spot_only = True`. Биржи
размещают BTC3L, ETHUP, BTCBULL и подобные на спотовом рынке, и ccxt честно
помечает их как spot — по флагам отличить нельзя. Для арбитража они непригодны:
внутри ежедневная перебалансировка позиции, цена следует за NAV, а не за
базовым активом, и видимая разница между площадками неисполнима. Распознавание
по имени: маркер плеча засчитывается, только если остаток имени сам торгуется
как обычный актив — иначе под шаблон попал бы токен, чьё имя случайно
оканчивается на UP или BEAR. Фильтр применяется и при сборе, и при расчёте,
поэтому уже накопленную историю пересобирать не нужно. Переключатель есть
в боковой панели на страницах связок и монитора.

**Свежесть.** Котировка старше `staleness_sec` в расчёт не идёт. Это
главный предохранитель: наивная протяжка застывшей цены фабрикует
арбитраж, которого не было. Внутри допустимого возраста протяжка
разрешена — иначе площадки почти никогда не совпадут по времени.

## Как ищутся связки

Прямой перебор невозможен: 80 активов и 4 ноги дают 512 тысяч маршрутов
в каждой из 10 тысяч точек истории — 5 миллиардов вычислений.

Поэтому два шага.

**Кандидаты.** Маржа — произведение курсов, в логарифмах — сумма.
Значит лучшую цепочку ищет алгебра max-plus: «умножение матриц», где
вместо суммы произведений берётся максимум сумм. Одно такое умножение
сразу даёт лучший двухшаговый переход между всеми парами активов;
повторное наращивание даёт три шага, четыре и так далее. Делается это
на прореженной по времени выборке (~400 точек).

**Точный расчёт.** Отобранные маршруты (обычно несколько сотен) считаются
уже по всей истории. Это дёшево и даёт полный временной ряд для графика.

Восстановление маршрута берёт таблицы `argmax` того момента времени,
на котором маршрут был найден, — иначе для кандидатов из середины
истории восстанавливался бы не тот путь, что дал высокий балл.

### Сортировка

| Режим | Когда полезен |
|---|---|
| по доле прибыльного времени | по умолчанию: связка с редкими, но реальными окнами полезнее той, что стабильно чуть ниже нуля |
| по лучшей марже за период | искать пиковые возможности |
| по типичной марже | строгий критерий, чаще всего пусто — рынок эффективен |
| по марже в последней точке | что происходит прямо сейчас |

## Ограничения источников

| Источник | Что даёт | Лимит |
|---|---|---|
| ccxt (биржи) | OHLCV, до 1000 свечей за запрос | внутренний rateLimit каждой биржи |
| GeckoTerminal top-pools | цена и резерв 20 пулов за запрос | 30 запросов/мин, ключ не нужен |
| GeckoTerminal OHLCV | до 1000 свечей на пул | тот же лимит, 10 страниц пулов бесплатно |

Отсюда двухуровневая схема сбора DEX: текущие цены всех 100 пулов
обновляются за 5 запросов (~10 секунд), а история набирается фоном
по одному пулу за раз. Полная глубина в 7 дней на 100 пулов —
порядка 30–40 минут после запуска.

**Чего сделать нельзя на бесплатных данных:**

- исторические котировки агрегаторов (KyberSwap, OpenOcean, ParaSwap,
  LI.FI, SushiSwap, Jupiter) — у них нет и не будет исторического API,
  они отвечают только на вопрос «сколько получу сейчас»;
- точная глубина V3-пулов в прошлом — нужна archive-нода или сабграф
  с полной картой тиков;
- межбиржевой спред по акциям и металлам — бесплатные фиды
  консолидированные и с задержкой 15 минут, а консолидированный фид
  по построению не показывает разницу между площадками.

## Монитор

Набор адаптеров с общим интерфейсом. Работают по-настоящему:

- **Спред между крипто-биржами** — один актив на разных площадках;
- **Депег стейблкоинов** — отклонение от номинала, самый надёжный сигнал;
- **Базис спот ↔ перп** — дельта-нейтральная позиция, доход плюс фандинг;
- **DEX против CEX** — цена в пуле BNB Chain против биржевой, котировка
  берётся прямо из смарт-контракта через существующий `dexes.py`.

Акции и металлы — заглушки с рабочей структурой. Если появится платный
фид с котировками в разрезе площадок, достаточно реализовать
`fetch_by_venue()` в `DelayedInstrument` и снять флаг `tradable`.

## Что показано в таблице связок

| Колонка | Смысл |
|---|---|
| Связка | цепочка обменов от стартового актива и обратно |
| Сейчас | маржа в последней точке истории — единственная, что относится к настоящему |
| Макс | лучшая маржа за выбранное окно |
| В плюсе | какую долю времени связка была прибыльна |
| Окно средн | типичная длительность возможности: столько времени обычно есть, чтобы зайти и провернуть обмен |
| Ликвидн. | самый мелкий пул в цепочке — он и ограничивает объём |
| Маршрут | площадки **по порядку исполнения**, пронумерованы: `1·biswap → 2·pancakeswap_v3` |
| Сеть | в какой сети идут обмены |
| Перев. | нужен ли вывод между площадками |
| Токены | расшифровка тикеров маршрута |

Остальные колонки прячутся переключателем «Показать все колонки»: на узком
экране пятнадцать столбцов не помещаются, а решение принимается по восьми.

Под графиком — блок **«Обмены по порядку»**: для каждой ноги площадка, сеть,
ликвидность пула и ссылка «открыть обмен» с уже подставленными адресами
контрактов. Ссылку можно открыть во встроенном браузере кошелька и свопнуть
сразу. Форматы адресов собраны в `links.py`, словарь `SWAP_URL` — если
какая-то площадка сменит адрес страницы, править нужно только там.

### Переводы между площадками

Связка, где все обмены идут в одной сети на DEX, — это последовательность
свопов из одного кошелька. Как только в цепочке появляется биржа или вторая
сеть, между ногами возникает перевод: комиссия сети, время подтверждения,
иногда заморозка вывода. Расчёт этого не учитывает, поэтому такие связки
помечаются в колонке «Перев.» и по умолчанию отфильтрованы переключателем
«Только без переводов».

## Оповещения в Telegram

Считаются после каждого сбора по свежим данным и уходят в чат, если связка
прошла порог. Настраивается двумя секретами в репозитории:

| Секрет | Что это |
|---|---|
| `TELEGRAM_BOT_TOKEN` | токен бота от [@BotFather](https://t.me/BotFather) |
| `TELEGRAM_CHAT_ID` | идентификатор чата — можно узнать у [@userinfobot](https://t.me/userinfobot) |

Без них шаг молча пропускается.

Пороги задаются переменными в `collect.yml`:

```yaml
ALERT_MIN_MARGIN: "0.3"        # чистая маржа сейчас, %
ALERT_MIN_LIQUIDITY: "200000"  # минимальный пул в цепочке, $
ALERT_MAX_PER_RUN: "5"         # сколько связок за прогон
ALERT_MUTE_MINUTES: "90"       # сколько молчать о той же связке
```

Три решения, без которых оповещения превращаются в мусор:

- **отбор по марже «сейчас», а не по максимуму за период** — красивый пик
  недельной давности к делу не относится;
- **порог по ликвидности** — на мелком пуле маржа неисполнима;
- **память об отправленном** — одна связка живёт десятки минут и попала бы
  в каждый прогон; повтор придерживается на `ALERT_MUTE_MINUTES`.

В сообщении: маршрут, маржа, сеть, узкое место по ликвидности, типичное окно,
ссылка на обмен для каждой ноги и оговорка, что расчёт исторический и окно
могло закрыться.

## Проверки

```bash
python -m history.tests.test_math       # математика, данные с известным ответом
python -m history.tests.test_pipeline   # сквозной прогон, без сети
python selftest.py                      # доступность внешних источников
```

`test_math` подкладывает рынок с заранее заложенной связкой и требует,
чтобы поиск нашёл именно её, а маржа совпала с теоретической до шестого
знака. Отдельно проверяется, что на согласованных курсах связок
не находится вообще — то есть ложных срабатываний нет.

`test_pipeline` пишет синтетические свечи в настоящую базу и прогоняет
весь путь до данных графика, проверяя в том числе, что прибыльное окно
обнаружено ровно там, где было заложено.

## Что этот инструмент не делает

История не позволяет торговать. Её ценность в другом: увидеть, как часто
возникает спред по конкретной связке, сколько он живёт, какая доля
находок — артефакт данных, а какие пары структурно стоят внимания.

На BNB Chain всё, что видно на минутной истории, забирают MEV-боты
в том же блоке. Практический смысл — аналитика и отбор пар, а не
торговый сигнал для ручного исполнения. Короткие одиночные всплески
на графике почти всегда неисполнимы; интерес представляют связки
с высокой долей прибыльного времени и длинными окнами.

Перед любой реальной сделкой прогоняйте найденное через основной
калькулятор — он считает по настоящему стакану с реальной глубиной.
